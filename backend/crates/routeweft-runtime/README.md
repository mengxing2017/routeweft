# routeweft-runtime

Optional Tokio host scheduler over the synchronous routing/dataset crates. Hosts resolve and authorize immutable paths before calling it. `RuntimeConfig` controls resident handles, load and query concurrency, bounded admission, queue timeout, load capacity/memory budget and query work budgets. Defaults use city capacity; regional hosts must configure their own limits.

`Runtime<EngineLoader>` accepts native `DatasetIdentity`, `Point`, `QueryOptions` and returns native routing results. Custom `Loader` implementations allow host adapters and deterministic tests. `execute` exposes the same bounded scheduler for host-owned result mapping.

Concurrent loads of one dataset share initialization; every successful waiter verifies the full expected identity. Eviction removes only the cache reference. Resident admission survives while any engine handle is held. Failed loads are retryable. Optional `Arc<dyn Send + Sync>` guards keep host files alive until actual synchronous loading exits.

`load_with_lease` limits waiter time without interrupting the underlying load. `validate_dataset` always opens staged files afresh and waits for actual completion before checking the deadline. It cannot promise hard cancellation of `Engine::open`. Query cancellation is cooperative; dropping/expiring the waiter signals the blocking query, which retains CPU/admission permits until it exits.

For publications that can add or recustomize MLD without changing the base graph, use `EngineResourceIdentity { dataset, mld_sha256 }` with `load_resources` / `load_resources_with_lease`. Supply the SHA-256 of the **complete** `routing.mld` file from a trusted delivery receipt, including its trailing checksum. `None` requires the artifact to be absent. Native `EngineLoader` verifies this digest against bytes read during normal accelerator loading, without a second file read. The digest also pins the artifact format and customization parameters. Cache hits verify the full base identity and do not reopen files; authorized paths and their contents must remain immutable.

Each distinct resource identity has its own single-flight cache entry. Prewarm the new immutable publication with `load_resources`, wait for success, then switch the host's active publication identity; subsequent queries must use that same identity. Old handles keep working and retain resident admission. Budget for old and new engines together during a switch. `evict(dataset_id)` removes all completed revisions of that graph, retaining in-flight loads until completion. Rollback can reuse a still-cached previous identity.

`validate_resources` authenticates staged base and accelerator files afresh, without populating the cache. It retains the same completion/deadline and file-lease guarantees as `validate_dataset`. After validation, release the staged handle before prewarming when resident capacity is limited. Custom loaders must implement `open_resources` to verify the resource identity; its default rejects these calls.

The original `load` / `load_with_lease` APIs retain dataset-only caching for compatibility. Hosts must adopt the resource-aware APIs to detect same-graph accelerator upgrades. The legacy cache is separate from exact resource entries, so a legacy engine with optional MLD cannot satisfy a request that explicitly requires no MLD. This library does not discover active publications or perform host startup prewarming automatically.
