# ADR 0001：先验证纯内存路由内核

历史决策：后续接口与数据集实现已由 [ADR 0002](adr-0002-dataset-and-routing.md) 补充替代。下文记录 P0 起点，不表示当前缺少磁盘引擎。

状态：P0 原型决策已采用；持久格式及稳定公开 API 尚未冻结。

新增一个有实际实现的 `routeweft-routing` crate，依赖现有零基础设施领域 crate `routeweft-domain`。保留旧 crate 路径和默认 CLI 行为，不同时做全面重命名。暂不建立空 dataset/preprocess crate。内核不依赖 daemon 或异步运行时，不引入消费者协议。

使用调用方提供的有向图及正整数毫秒权重。搜索键必须保留禁止序列所需的边历史，否则通过不同道路到达同一节点会错误丢弃合法路线。P0 用 Dijkstra 验证语义；线性限制扫描和历史复制仅适合小图，后续应在固定城市输入下评估限制自动机和内存预算。

持久格式草案：WGS84 经纬度、明确单位、版本化 manifest、受控文件名、输入/profile/构建指纹和每文件校验；固定端序与整数宽度，不序列化 Rust 原始布局。尚未选定文件编码、哈希算法或加载方式，不能称为已支持格式。P1 实施前应另立 ADR，验证损坏文件、路径穿越、上限和确定性。

公开 API 目前仅 `Engine::new/route/coordinate`、Edge、Path、SearchBudget 和 Error；均为实验接口。节点查询不能替代坐标吸附，多次查询不能替代多途经点连续限制搜索。后续增加 Nearest、持久数据集和错误契约时应明确破坏性变更。
